# 新闻原文

每次追问都用这个技能，并调用 `fetch_news`。开场那句结论仍用 `news-facts`（开场需要绑定股票）。

调用 `fetch_news`。参数：

- `ts_code`：有绑定个股时传入；**主题/市场/宏观新闻可省略**
- `keyword`：用户要搜的原话或事件词。无 `ts_code` 时必填。例如「最新的财经资讯」「物理AI」「国家政策」。不要在前面加股票名称
- 历史类比：对同一主题再搜一轮，keyword 带「此前 / 上次 / 复盘」等，用来找类似新闻之后市场交易了谁

有股票时工具请求 `GET /api/stocks/news?q={代码}&keyword={原话}`；无股票时 `GET /api/stocks/news?keyword={原话}`。不要改地址。

返回：

- `query`：实际搜索词，和 keyword 相同。
- `facts[]`：这次搜索到的新闻，`id` 形如 `nw.1`。来源是东方财富搜索等，不限于某只股票，标题里没有股票名也要列出。
- `rows[]`：时间、标题、来源、摘要。追问只按这些字段写。
- `matched` 为 0：写「按这个搜索没有搜到新闻」。
- `unavailable` 里有 google：只说明 Google 这次没返回。`facts` 里已经有新闻就按那些写。

回答只依据这次 `fetch_news` 的 `rows`/`facts`。不要把开场近 3 日 detail 里的公告写成这次搜索结果。
**已明确个股** → 以该股为主线；**未指定个股** → 全面冲击地图（含受益/承压名单）。允许点名板块与个股。
传闻不坐实。数字和标题只抄返回 text。重复标题不叠加。不追求字数上限。
不编工具未给出的涨跌幅；不给目标价或概率百分比。禁止开场 JSON。写法见 reply.md；末尾可写「可以接着问」。
